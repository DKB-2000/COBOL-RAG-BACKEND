# 식별자 표현 보완 후 생성 평가 v2

2026-10-27, identifier-aware 검색 프로필로 공개 고정30문항을 각1회 재평가했다.
자동 재시도 없이30건을 수집했고 Codex Orchestrator가 원본 코드와 인용을 대조했다.
인용까지 충족한 답변은 **13/24 → 15/24**로 늘었다. 개선3건과 회귀1건을 함께 보존한다.
독립 사람 검수는 아직 완료하지 않았다.

## 동일 기준 전후 비교

| 항목 | v1 original | v2 identifier-aware |
|---|---:|---:|
| 실제 질문 수 | 30 | 30 |
| answered / refused | 14 / 16 | 15 / 15 |
| unavailable / error | 0 / 0 | 0 / 0 |
| 내용 정답 / 답변 가능 전체 | 14/24,58.3% | 15/24,62.5% |
| 정답·완전성·인용 모두 충족 | 13/24,54.2% | **15/24,62.5%** |
| 올바른 근거 부족 거절 | 6/6 | 6/6 |
| 반환 인용 ID 연결 | 18/18 | 18/18 |
| 인용된 사실의 의미적 근거성 | 22/23 | 27/27 |
| 인용의 충분성 | 22/23 | 27/27 |
| HTTP p50 / p95 | 1.735초 / 5.688초 | 1.630초 / 3.032초 |

의미 지표는 같은 `answer-rubric-v1`에 따른 **Codex1차 판정**이다. 답을 반환하지 못한
답변 가능 문항9건도 전체24건의 실패에 포함한다. 반환한 답변15건만 분모로 삼아 전체
정확도가100%라고 보고하지 않는다. v2의 생성 주장16개를 원자 사실27개로 나눴으며
두 실행의 출력이 달라 사실 분모도 다르다. ID 연결 성공만으로 의미적 근거성을 인정하지 않았다.

순차 HTTP 각30건, nearest-rank로 지연을 계산했다. `/query` 안의 검색·생성·직렬화를
포함하고 별도 `/search`·채점은 제외한다. 두 번의 단일 실행 관측값으로, 속도 개선의
인과관계나 운영 SLA를 입증하는 부하 시험은 아니다.

## 개선과 회귀

| 질문 | v1 | v2와 실제 인용 근거 |
|---|---|---|
| q012 거래 테이블 최대 건수 | 근거 부족 거절 | 20건, WORKING-STORAGE의 `OCCURS 20 TIMES` |
| q013 거래 순회 인덱스 | WS-INDEX 정답이나 인용 불충분 | MAIN-PROCESS의 `PERFORM ... VARYING WS-INDEX FROM 1 BY 1`과 종료 조건 |
| q014 잔액 계산 호출 대상 | 근거 부족 거절 | POST-TRANSACTIONS의 `CALL "ACCOUNT-BALANCE"` |
| q002 고객 입력 파일 끝 감지 | 정답·인용 충족 | **refused / invalid_citations로 회귀** |

q002의 별도 검색 재구성 문맥에는 READ-CUSTOMER의
`AT END SET END-OF-FILE TO TRUE`가 포함돼 있다. 이번 실패는 HTTP 계약상 인용 검증 실패다.
거절되기 전 모델 출력과 잘못된 ID는 수집하지 않았으므로 원인을 특정 식별자나 모델 변동성으로
단정하지 않는다. 이 건을 올바른 근거 부족 거절이나 검색 누락으로 계산하지 않았다.

답이 있지만 반환하지 못한 문항은 q002, q003, q004, q005, q006, q010, q011, q018, q022다.
q002 외8건은 `insufficient_evidence`다. q025~q030의 원본에 없는 기능·정보 질문은 모두
`insufficient_evidence`로 거절했다. 실패를 다시 호출하거나 성공 응답으로 교체하지 않았다.

무료 검색 검증의 **근거 포함16/24·기존13건 보존**과 실제 생성의 **인용 충족15/24·회귀1건**은
서로 다른 측정이다. q002는 근거를 검색해도 최종 답변이 실패할 수 있음을 보여준다.

## 고정 조건과 추적

질문30건·근거·rubric·공개 합성5개·원문/청크ID·최대10개/4000자 정책을 유지했다.
검색 표현만 [식별자 보완](identifier-aware-retrieval-v1.md)으로 바꿨다. 같은 로컬 다국어
encoder에서 원래 표현과 식별자 정규화 표현을 동일 비중으로 결합하고 L2 정규화한다.
각 표현의 입력 상한은128토큰이다. 새 collection에5문서52청크를 색인하고 사전 검사에서
30문항의 검색 문맥이 새 프로필 기준과 일치함을 확인한 뒤 유료 요청을 보냈다.

생성 설정은 gpt-6-luna, reasoning none, 출력 상한1000토큰, SDK 자동 재시도0으로 동일하다.
실제 공급자 model ID·token usage·청구액은 HTTP 계약에서 관측하지 않아 null로 남겼다.
승인된 추가 견적0.03~0.10USD는 실제 청구액이 아니다. 로컬 전용 COBOL은 사용하지 않았다.

원본 응답·요청 의도·실행 manifest·검수 템플릿·Codex 주석은 Git 제외
`artifacts/generation-v2-*`에 있다. 공개 가능한 응답/판정/요약/입력·코드 해시는
[버전 관리 결과](../data/evaluation/results/generation-evaluation-v2.json)에 보존했다.
[v1 결과](generation-evaluation-v1.md)는 변경하지 않았다.
`reconstructed_context`는 별도 검색으로 재구성한 자료이며 실제 모델 프롬프트 캡처가 아니다.

아래는 수집된 응답과 주석만 사용하는 오프라인 집계 명령이다. 추가 생성 요청을 하지 않는다.

```powershell
.\.venv\Scripts\python.exe scripts/evaluate_generation.py --prefix generation-v2 --score artifacts/generation-v2-reviews-codex.jsonl
```

## 한계와 다음 단계

같은5개 합성 파일과 개발에 사용한30문항을 재사용했으며 독립 holdout이나 실제 사내 업무 코드
성능이 아니다. 독립 사람 검수도 남아 있다. q009는 세 전달 항목을 묻는 질문에 USING의
세 이름이 충분한 근거라고 판정했고, q024는 필드 이름을 묻는 질문에 FORMAT-DATE와
USING의 `LK-FORMATTED-DATE`가 충분하다고 판정했다. rubric의 보충 선언 정보를 모두
답변에 나열하도록 강제하지 않은 v1 기준을 유지했다.

한정된 개선 루프는 여기서 종료한다. 순증2건의 근거 있는 답변 개선과 인용 실패1건을
공개하고 현재 프로필을 유지한다. 추가 유료 호출·검색 가중치/모델 탐색은 하지 않았다.
다음 제출 작업은 행 번호 COBOL 청킹 호환성, Docker 등 재현 실행과 최종 데모/문서다.
