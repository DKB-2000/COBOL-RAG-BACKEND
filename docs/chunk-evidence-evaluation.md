# 실제 검색 청크의 코드 근거 평가

## 목적과 방법

파일 순위 MRR과 실제 상위 청크의 답변 근거 포함률을 구분한다. 기존 질문 v1과 세 기준선 결과는 변경하지 않고, answerable 24건에 대한 보조 주석 `data/evaluation/evidence-v1.jsonl`을 추가했다. 답변 불가 6건은 이 평가에서 제외한다.

주석은 원본 COBOL을 읽고 작성한 코드 조각 기반 평가 기준이다. 외부 모델이나 독립 검수자의 판단을 사용하지 않았다. 각 필수 근거 단위는 출처와 하나 이상의 코드 조각(`anchors`)으로 구성된다. 같은 출처의 **한 청크 안에 그 단위의 모든 조각**이 있어야 충족한다. 여러 필수 단위는 서로 다른 청크에서 충족해도 된다. 대소문자와 연속 공백을 정규화하며 COBOL 식별자 경계를 검사한다.

- `symbol_coverage`: 기대 심볼 중 정답 출처 청크의 본문에 나타난 비율. 선언과 호출도 일치할 수 있는 보조 지표다.
- `evidence_hit`: 필수 근거 단위를 하나 이상 찾았는지.
- `evidence_coverage`: 필수 근거 단위 중 찾은 비율.
- `evidence_complete`: 모든 필수 근거 단위를 찾았는지. 아래 주 지표다.
- `source_hit`: 기대 출처 중 하나라도 찾았는지. 근거 포함을 보장하지 않는다.
- `context_characters`: 가져온 원문 청크의 문자 수 합계. 토큰 수나 생성 프롬프트 길이가 아니다.

비율은 질문별 값을 24건에 걸쳐 평균한다. k는 출처 중복 제거 없는 실제 청크 수다. 파일 단위는 한 파일이 한 청크이며 총 5개뿐이다. 구조 방식은 총 52개이고 저장된 상위 10개를 사용한다. 구조 기준선의 원문 해시와 현재 소스를 대조한다. 파일 기준선은 저장된 출처 순서와 현재 파일 본문으로 복원하므로 과거 파일 본문의 동일성을 독립적으로 증명하지는 못한다. 입력 파일 해시는 새 결과에 기록한다.

## 결과

필수 근거를 모두 포함한 질문 수 / 전체 질문 수:

| 검색 방식 | @1 | @3 | @5 | @10 | 평균 원문 문자 수 @5 |
|---|---:|---:|---:|---:|---:|
| 파일 단위 | 5/24 | 15/24 | 24/24 | 24/24 | 11,374.0 |
| raw 구조 청크 | 0/24 | 0/24 | 1/24 | 6/24 | 1,117.7 |
| 경로·심볼 문맥화 구조 청크 | 0/24 | 0/24 | 3/24 | 9/24 | 1,422.0 |

| 검색 방식 | 심볼 포함률 @5 | 출처 적중률 @5 | 필수 근거 완전 포함률 @5 |
|---|---:|---:|---:|
| 파일 단위 | 1.0000 | 1.0000 | 1.0000 |
| raw 구조 청크 | 0.2083 | 0.5000 | 0.0417 |
| 문맥화 구조 청크 | 0.2500 | 0.5417 | 0.1250 |

문맥화의 파일 순위 MRR 0.5493과 파일 Hit@3 0.8333은 전체 청크 검색 후 출처를 중복 제거한 지표다. 위 표의 실제 청크 @3과 다르다. 파일 단위 @5는 모든 파일을 가져오므로 높은 근거 포함률만으로 효율적인 검색이라고 판단할 수 없다. 문맥화 @10의 평균 원문은 2,943.0자다. 동일 k 비교는 동일 문맥 예산 비교가 아니며, 동일 토큰 예산 실험은 아직 수행하지 않았다.

## 출처만 찾고 근거를 놓친 경우

문맥화 상위 5개에서 기대 출처를 찾았지만 필수 근거가 부족한 질문은 10건이다:

`q003, q006, q008, q014, q016, q018, q020, q021, q023, q024`

raw 구조 청크는 11건이다:

`q003, q006, q007, q008, q009, q014, q016, q020, q021, q023, q024`

예를 들어 q014는 호출자의 `POST-TRANSACTIONS`에서 실제 `CALL ACCOUNT-BALANCE`를 찾아야 하며, q016은 `FORMAT-REPORT-DATE`의 `CALL DATE-UTILITY`를 찾아야 한다. 호출 대상 파일의 PROGRAM-ID만 찾는 것은 근거 충족으로 처리하지 않는다. 질문별 누락 코드 조각과 검색 청크 ID는 결과 JSON에 저장된다.

## 한계와 적용 판단

문맥화는 raw 구조 대비 개선됐지만 상위 5개 근거 완전 포함률은 12.5%, 상위 10개도 37.5%다. 구조 청킹의 API 적용은 보류하고 기존 파일 단위 API를 유지한다. 이는 현 API가 답변 생성에 충분하다는 승인도 아니다. 답변 생성 및 거절 정책은 아직 별도 단계다.

이 평가는 고정된 합성 코드 5개와 수작업 주석의 문자열 일치 검사다. 주석의 의미적 충분성이나 실제 생성 답변의 정확성을 검증하지 않는다. 주석·문자열 리터럴도 텍스트 일치로 계산될 수 있고, 같은 근거를 다른 형태로 표현한 코드는 놓칠 수 있다. 언어 불일치는 가능한 원인일 뿐 이번 결과만으로 확정할 수 없다. 동일 질문·근거 기준의 후속 [다국어 임베딩 비교](multilingual-embedding-baseline.md)는 별도 결과로 보존한다.

## 실행과 재현

```powershell
.\.venv\Scripts\python.exe -m legacy_rag.evaluation.run_evidence_evaluation
```

저장된 순위를 분석하므로 모델 다운로드나 Chroma 재색인은 없다. 기본 결과는 `data/evaluation/results/chunk-evidence-v1.json`이다. `--data-root`, `--dataset-path`, `--evidence-path`, `--file-baseline-path`, `--structured-baseline-path`, `--contextual-baseline-path`, `--output-path`로 경로를 지정할 수 있다. 같은 경로·입력에서 결과는 결정적으로 생성된다.

동일 입력 재실행의 SHA-256은 두 번 모두 `3def8ea483a43b022db0d937bca255cabb578aed50ce238f61a57a988bea22f8`였다. 절대 입력 경로가 결과에 포함되므로 다른 경로에서는 이 해시와 다를 수 있다. 전체 pytest 54건과 Ruff 검사를 통과했다.
