## 남은 실패와 판정

- API q004: 문단명은 맞지만 실제 문맥에 MAIN-PROCESS의 무효 분기가 없어 근거 불충분.
  q006은 답변 가능한 입금/출금 분기 질문을 근거 부족으로 거절했다.
- Qwen q004/q022/q024: 관련 사실은 일부 맞지만 요청한 문단명·필드명을 답하지 않았다.
  q006은 파일 SELECT를 거래 유형 분기로 오인했고, q016은 DATE-UTILITY 대신 문단명을 답했다.
- Qwen q007: 내용의 코드02는 맞지만 실제 인용은 APPLY-WITHDRAWAL뿐이어서 입금 근거 부족.
- Qwen q026/q029/q030: CICS 전송·월말 삭제·XML 생성 기능을 원문에 없이 주장했다.
  q029는 단순 집계 문단을 삭제 기능으로 설명했다. 세 건 모두 정답이나 올바른 거절로 세지 않는다.
- Qwen q010/q015/q018: 질문형 종결은 표현 문제로 별도 기록한다. 이전 Qwen q007에서도
  같은 표현을 내용·인용과 분리해 판정했으므로 이번에 새로운 감점 기준을 추가하지 않았다.

의미 판정은 전체 원문상의 내용 정답, 실제 제공 문맥의 근거성, 실제 인용의 뒷받침을 구분한다.
반환된 답변만 분모로 삼아 정확도를 높이지 않고 답변 가능24문항 전체를 평가한다.

## 고정 조건과 완료 기준

- [검증된 BGE 문맥](reranker-api.md)의 실제 본문·순서와 같은 입력을 사용한다.
  모델 호출 직전에 시스템 지시·질문·청크 본문·출처·순서를 전문 대조한다.
- 기존 공개 질문·원문·`answer-rubric-v1`을 유지한다. 정답 주석은 모델 입력에 포함하지 않는다.
- 새 127.0.0.1:8014 API와 별도 Chroma에서 실제 `/query`를 실행한다.
  기존 서버/컨테이너·DB·과거 생성 결과는 교체하지 않는다.
- OpenAI Responses API는 reasoning none·출력1000토큰·store false·SDK 재시도0이다.
  사용자가 신규 유료 생성 최대30회를 승인했다. 실제 사용량과 청구액은 구분한다.
- Qwen은 기존 Q4_K_M digest와 num_ctx8192·출력1024·think false·keep_alive0을 유지한다.
  think false 전달만으로 모델의 생각 출력이 억제됐다고 가정하지 않는다.
- 내용 정답, 정답·완전성·충분한 인용 동시 충족, 근거 부족6문항의 올바른 거절을
  별도 분모로 평가한다. 답을 못 한 가능 문항도 전체24건의 실패에 포함한다.
- 채점은 Codex Orchestrator가 실제 원문과 인용을 대조한다. 독립 사람 검수는 미완료다.
- 순차 HTTP 지연에는 BGE 검색·문맥·생성·응답 직렬화가 포함된다. 준비 검사의
  모델 로딩/INT8 변환은 분리한다. 공급자 load/prompt/eval 시간도 원본에서 관측한다.

공식 [모델 안내](https://developers.openai.com/api/docs/models/gpt-6-luna)와
[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)를 확인했다.
기존 어댑터의 모델·프롬프트·생성 설정은 변경하지 않았다.

## 수집과 재개

```powershell
.\.venv\Scripts\python.exe scripts/evaluate_reranked_generation.py --provider ollama
.\.venv\Scripts\python.exe scripts/evaluate_reranked_generation.py --provider openai
```

위 명령은 오프라인 입력 검사만 수행한다. 실제 실행에는 `--execute`를 추가한다.
OpenAI 실행은 유료이며 해당 작업의 별도 승인이 필요하다. 키는 프로세스 환경 또는
Windows 사용자 환경 변수 `OPENAI_API_KEY`에서 읽고, 값은 기록하지 않는다.
`.env`는 이 수집기도 자동으로 읽지 않는다. 공급자 호출 예산은 각30회다.

질문별 호출 의도를 `artifacts/bge-generation-v1-<provider>-calls.jsonl`에 fsync한 뒤
공급자를 호출한다. 이미 시도한 질문은 응답을 받지 못했더라도 자동으로 반복하지 않는다.
기존 prefix는 덮어쓰지 않는다. 실패/실행 공백 뒤에는 원본을 보존하고, 예를 들어 다음처럼
아직 공급자 호출을 시도하지 않은 문항만 새 prefix로 재개한다.

```powershell
.\.venv\Scripts\python.exe scripts/evaluate_reranked_generation.py --provider ollama --execute --resume-from bge-generation-v1-ollama --prefix bge-generation-v1-ollama-cont1
```

이 재개는 실패 문항의 재측정이 아니다. 이전 실패도 전체30문항의 원본 집계에 유지한다.
원시 요청·공급자 응답·usage·검수는 Git 제외 artifacts에 두고, 공개 결과에는 생각 텍스트를
포함하지 않는다. 실행 중 임시 idle 절전 가드는 프로세스 종료 시 해제한다.

## 확인된 운영 실패

첫 q001은 BGE 준비 검사 후 Qwen 모델 로딩에서 실패했다. Ollama HTTP500의
`CPU_REPACK` 약1.76GB 버퍼 할당 오류였으며 API는 `unavailable/generation_unavailable`을
반환했다. HTTP7.804467초, 공급자 처리0.759880초다. 이를 내용 오답이나 올바른 거절로
바꾸지 않는다. 원본은 `artifacts/bge-generation-v1-ollama-*`에 보존했다.

사용자가 다른 앱을 닫아 메모리를 확보하고 실제 API 통합 평가를 유지하도록 선택했다.
남은29건은 `bge-generation-v1-ollama-cont1-*`에서 완료했으며 q001을 재호출하지 않았다.
같은 PC에서 BGE와 Qwen을 함께 실행하는 메모리 제약도 결과의 일부다.

이전 [API/Qwen 비교](ollama-generation-comparison.md)의 근거 충족15/24와
이번 BGE [검색 근거22/24](reranker-api.md)를 실제 답변 정확도로 대신하지 않는다.
이번 실제 API의 근거 충족도22/24로 같았지만 서로 별도로 측정한 지표다.
공유 PC·환경 변경·단일 실행·개발 평가셋이라는 한계를 유지한다.
