# 구조 청크 문맥화 임베딩 비교

## 입력과 평가 방법

합성 COBOL 5개를 구조 청크 52개로 나누고, `questions-v1.jsonl`의 answerable 질문 24개로 평가했다. 모델은 기존 Chroma 기본 ONNX `all-MiniLM-L6-v2`, 거리는 cosine이다. 문서 임베딩 입력에 상대 경로와 구조 심볼을 추가했다.

```text
Source path: samples/account-balance.cbl
Symbol: APPLY-DEPOSIT

<원문 청크>
```

질문 임베딩에는 질문 원문을 입력한다. Chroma의 `documents`와 검색 결과 본문에는 원문 청크를 저장한다. 통합 테스트는 저장된 청크를 순서대로 이어 붙였을 때 입력 파일과 일치하는지, 문맥 문자열이 임베딩 함수에만 전달되는지 확인한다.

전체 청크를 점수순으로 조회하고 `source_path`를 중복 제거해 서로 다른 파일의 순위를 평가한다. 아래 Hit@k와 MRR은 파일 단위 지표다. 상위 k개 청크의 정답 문단 포함률이나 모든 필요 근거의 검색 성공을 의미하지 않는다.

## 결과

| 입력 | Hit@1 | Hit@3 | Hit@5 | MRR |
|---|---:|---:|---:|---:|
| 파일 단위 원문 | 0.2500 | 0.6667 | 1.0000 | 0.4979 |
| 구조 청크 원문 | 0.2917 | 0.7083 | 1.0000 | 0.5299 |
| 구조 청크 + 경로·심볼 | 0.2917 | 0.8333 | 1.0000 | 0.5493 |

구조 청크 원문 대비 Hit@3는 0.1250, MRR은 0.0194 개선됐다. 문서가 5개라 파일 단위 Hit@5는 품질 구분에 도움이 되지 않는다. 목표 MRR 0.60은 미달했고, 정답 파일 1위 비율도 7/24로 동일하다. 답변 불가 질문 6개는 이 평가에서 제외했다.

## 질문별 변화

숫자는 중복 제거 후 첫 정답 파일의 순위다. 정답 후보가 여러 파일이면 그중 가장 높은 순위를 사용한다.

| 질문 | 원문 → 문맥화 |
|---|---:|
| q011 거래 레코드 적재 | 4 → 2 |
| q015 계정 보류 메시지 | 5 → 3 |
| q017 계정 수·총잔액 집계 | 5 → 4 |
| q018 활성·보류 계정 구분 | 4 → 2 |
| q020 보고서 입력 파일 | 3 → 1 |
| q003 고객 레코드 검증 | 2 → 3 |
| q004 오류 파일 기록 | 4 → 5 |
| q006 입금·출금 구분 | 2 → 3 |
| q021 날짜 분리 | 1 → 2 |

5개 질문이 개선되고 4개가 회귀했으며 15개는 같았다. 경로와 심볼 추가가 파일 식별 신호를 강화한 것으로 추정하지만, 모든 질문에 유리하지는 않았다. 한국어 질문과 영어 코드 사이의 언어 불일치는 다음에 검증할 가설이며, 이번 실험만으로 주원인이라고 확정할 수 없다.

## 재현성

같은 설정으로 재실행한 집계 지표와 파일·청크 ID 순위가 같았다. 별도 새 Chroma 경로와 비교했을 때 score에서 최대 `1.1920928955078125e-7` 차이가 관찰됐다. 결과 JSON은 score를 소수점 6자리로 반올림해 기록한다. 검색 계산과 순위 결정은 원래 score를 사용한다.

현재 설정에서 정규화한 결과 파일을 두 번 생성한 SHA-256은 동일했다.

```text
7fa8788af3f506f225142f458d458785a65e1e5e957e87f087a69a4a87d71376
```

이는 확인한 실행 환경에서의 결과이며, 다른 플랫폼·라이브러리 버전의 바이트 단위 재현성을 보장하지 않는다. 결과 JSON에는 실행 경로도 포함된다.

## 재실행과 적용 상태

```powershell
.\.venv\Scripts\python.exe -m legacy_rag.evaluation.run_contextual_baseline
```

경로 옵션은 `--data-root`, `--dataset-path`, `--chroma-path`, `--structured-baseline-path`, `--output-path`다. 기본 출력은 `data/evaluation/results/contextual-structured-baseline-v1.json`이다. 파일 단위·raw 구조 기준선은 별도 결과 파일에 보존된다.

현재 최고 파일 검색 지표는 구조 청크 + 경로·심볼 조합이다. 실험 완료로 기록하되 검색 품질 게이트 통과로 처리하지 않는다. 후속 [실제 청크 근거 평가](chunk-evidence-evaluation.md)에서 상위 5개 근거 완전 포함은 3/24건이었다. 구조 청킹의 API 적용은 보류하며 P3 API는 파일 단위 청킹을 유지한다. 다음 실험 후보는 동일 구조 청크에서의 다국어 임베딩 비교다.
